# 状況

フェーズ 2 は、`SHOMEN_SECRET` が無いとプロセスごとにランダムな鍵を作る（`20260929-phase2-secret-fallback.md`）。複数のプロセスでこれが起きると鍵がそろわず、別のプロセスが出したフォームの CSRF トークンが合わずに 403 になる。

# 決定

`SHOMEN_ENV=production` のとき、`SHOMEN_SECRET` が未設定か 32 バイト未満なら起動に失敗し、変数名を含むメッセージを出す。`Shomen::Server.new(secret:)` で鍵を直接渡したときも、production では同じ長さを確かめる。production 以外は、フェーズ 2 のランダムな鍵のままにする。

# 理由

同じプロセスを並べるには、鍵がプロセス間でそろっている必要がある。本番で鍵が無いまま起動できると、1 プロセスでは動いて見え、台数を増やしたときに初めて 403 が出る。起動時に止めれば、デプロイの時点で気づける。32 バイトは、HMAC-SHA256 の出力長に合わせた下限である。

# 破棄した案

- どの環境でも `SHOMEN_SECRET` を必須にする（フェーズ 1 の受入が環境変数なしで通らなくなる）
- 本番で鍵が無いときは警告だけ出して起動する
- 鍵を直接渡したときは確かめない
