# 状況

`Shomen::Server.start` は `bind_tcp(host, port)` を呼び、`reuse_port` を渡していない。そのため、1 ホストで複数のプロセスが同じポートを使えない。

# 決定

`Shomen::Server.start` に `reuse_port : Bool = false` を足し、`bind_tcp` にそのまま渡す。1 ホストの複数プロセスは、同じポートを共有するか、別々のポートでロードバランサの後ろに並べる。

ポートを共有するときは、Linux で `net.ipv4.tcp_migrate_req=1`（カーネル 5.14 以降）を設定する。設定できない環境では、別々のポートにして、止めるプロセスをロードバランサから外してから SIGTERM を送る。

# 理由

Linux の `SO_REUSEPORT` は、同じポートへの接続をプロセス間に振り分ける。前段にプロキシを置かなくても、1 ホストで全コアを使える。ただし、ポートを共有したまま 1 つのプロセスが待ち受けを閉じると、そのソケットの受け付け待ちの接続はリセットされる。`tcp_migrate_req` を有効にすると、それらは残りのプロセスへ移る。これはカーネルの振る舞いで、フレームワークでは防げないので、運用の条件として書いておく。

# 破棄した案

- 1 プロセスをマルチスレッドにして全コアを使う（メモリ上のプロジェクションに排他が要るようになり、同じプロセスを並べる形と二重に考えることになる）
- 親プロセスが子プロセスを管理する仕組みを Shomen に入れる（プロセスの管理は systemd や Kubernetes に任せる）
