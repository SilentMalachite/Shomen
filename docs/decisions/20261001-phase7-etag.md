# 状況

仕様 10 と `20260929-scale-etag.md` は、GET ルートが検証子を返し、サーバがビルド ID と CSRF トークンを合わせて弱い `ETag` にし、一致する `If-None-Match` にはビューを呼ばずに 304 を返すと決めた。ルートが検証子を宣言する形、304 を返す場所、ビルド ID の作り方、ハッシュの形、どの応答に `ETag` を付けるかは決めていない。2026-10-01 にユーザーは、検証子をルートのメソッドで宣言し、フレームワークが `call` の前に呼ぶ形を選んだ（`docs/superpowers/plans/2026-10-01-phase7-overview.md`）。

# 決定

- GET ルートは `def validator(input : Input) : String` を定義できる。GET 以外のルートが定義したらコンパイルエラーにする。戻り値が `String` でなければコンパイルエラーにする
- ルートの `handle` は、`csrf_token`、`must_see`、`target` を設定した後、`call` の前に `validator(input)` を呼ぶ。`Shomen::ETag.tag(validator, csrf_token, target)` が `If-None-Match` に一致したら、`call` を呼ばずに 304 の応答を返す
- 一致しなければ `call` を呼ぶ。返った応答の状態が 200 で、SSE でなければ、`ETag` を付ける。ほかの応答（リダイレクト、例外で終わった要求、SSE）には付けない
- 304 と、`ETag` を付けた 200 には、応答が `Cache-Control` を持っていなければ `Cache-Control: private, no-cache` を付ける
- `ETag` は `W/"…"`。中身は、ビルド ID、CSRF トークン、`Shomen-Target`（無ければ空）、検証子を、それぞれバイト長を前に付けてつなぎ、SHA-256 の 16 進の先頭 32 文字にしたもの
- `If-None-Match` はカンマで区切った一覧として読み、各値の `W/` を外して弱い比較で照合する。`*` は一致とみなす
- ビルド ID は `Shomen::BUILD_ID`。コンパイル時にマクロの `run` で乱数の 16 バイトを 16 進にして埋め込む。コンパイルのたびに変わり、同じバイナリのプロセスは同じ値を持つ

# 理由

検証子を `call` の外で宣言すれば、一致したときにビューを呼ばないことをフレームワークが守る。`call` の中で比べる形では、ルートの書き方次第でビューが呼ばれる。GET 以外で宣言できなければ、POST の応答を 304 にする誤りがコンパイル時に止まる。

検証子を `call` より先に計算するので、本文のリードモデルは検証子のときと同じか新しい。逆の順だと、古い本文に新しい `ETag` が付き、データが変わらない間、古い本文が 304 で使われ続ける。リードモデルを 2 回読むが、`catch_up` の 2 回目は差分だけを読む。

1 つの URL は `Shomen-Target` によって文書か断片を返し、`Vary: Shomen-Target` を付けている。`Shomen-Target` をハッシュに入れれば、ブラウザが文書の `ETag` で断片を問い合わせても 304 にならない。バイト長を前に付ければ、区切りの位置をずらした 2 組の値が同じハッシュにならない。

マクロの `run` は標準ライブラリだけで動き、git もビルド時の環境変数も要らない。プロセスの起動時に決めると、ロードバランサの後ろのプロセスごとに `ETag` が変わり、別のプロセスに当たった要求が 304 にならない。

# 破棄した案

- `call` の中で `return not_modified if fresh?(value)` と書く（ビューを呼ばないことをルートが守る）
- `call` の後に検証子を計算する（古い本文に新しい `ETag` が付く）
- ビルド ID を git のコミットから作る（ビルド時に git が要る）
- ビルド ID をプロセスの起動時に決める
- ビルド ID を環境変数で渡す（渡し忘れたデプロイで古いマークアップが 304 で使われ続ける）
