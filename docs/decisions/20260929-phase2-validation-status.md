# 状況

フェーズ 2 は、検証エラーのとき同じフォームを 422 で描き直すとしている。検証の書き方は定めていない。

# 決定

検証はルートの `call` の中でアプリが書く。フレームワークは `render(view, status: 422)` のように、`render` に `status` を渡せるようにするだけにする。型変換の失敗と欠けたフィールドは、これまでどおり 400 である。

# 理由

検証 DSL やエラーオブジェクトは仕様に無い。値を入れ直したフォームを描くのはビューの仕事である。

# 破棄した案

- `Input` に `validate` を持たせ、フレームワークが 422 を返す
- 型変換の失敗も 422 にする
