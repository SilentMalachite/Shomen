# 状況

フェーズ 2 の `Server` は、urlencoded のフォーム本文を一度だけ読んで `URI::Params` にする（`20260929-phase2-form-input.md`）。当初は本文を上限なしで最後まで読んでいた。巨大な本文を同時に送られると、そのぶんだけメモリを使う。仕様は本文の大きさを定めていない。

# 決定

フォーム本文の上限を `Shomen::Server::MAX_FORM_BYTES`（1 MiB、1_048_576 バイト）とする。`Content-Length` が上限を超えていれば本文を読まない。`Content-Length` が無い本文は上限 + 1 バイトまで読み、超えたらそこで止める。どちらも 413 の HTML 文書（見出しは `Content too large`）を返す。上限ちょうどは受け付ける。この検査は CSRF の検査より前に行う。urlencoded でない本文は、これまでどおり読まない。

# 理由

フォームの値は短い文字列と整数だけなので、1 MiB で足りる。本文を読み終えないとトークンを取り出せないので、上限を超えた本文には CSRF の検査を行えない。403 を返すと、正しいトークンを送った利用者にも「拒否」と見え、原因がわからない。413 なら大きさが原因だとわかる。03-CONVENTIONS に従い、想定内の 4xx として例外を使わずに返す。

# 破棄した案

- 上限を設けない（当初の実装）
- 上限を超えた本文を空のフォームとみなし、403 にする
- 上限を設定で変えられるようにする（フェーズ 2 に必要な利用者がいない）
