# 状況

仕様 3 は、同じビューに対応する `label`（`for` かラップ）か `aria-label` が無い `input` をコンパイル時に拒否するとしている。1 つのマクロ呼び出しからは、兄弟要素が見えない。

# 決定

`Shomen::View` の `macro inherited` で、各サブクラスに `macro method_added` を置く。ビューで定義したメソッドごとに、展開前の本体を `stringify` して行単位で走査する。次のいずれかを満たさない `input` 呼び出しがあればコンパイルエラーにする。

- 同じメソッドに `label(..., for: "x")` があり、`input` に文字列リテラルの `id: "x"` がある
- インデントで見て `label ... do` ブロックの中にある
- `"aria-label": ` を持つ
- `type: "hidden"` を持つ（ラベルが不要な要素なので検査しない）

文字列リテラルと正規表現リテラルの中身は、呼び出しの検出から外す。エラーは `input needs a label` を含む。

# 理由

`method_added` は展開前の本体を整形済みの文字列で受け取るので、`html` の `title` 個数検査と同じ字句走査の方式が使える。メソッドごとに検査すると、ヘルパーメソッドに置いた `input` も検査から漏れない。hidden を除外しないと、CSRF のフィールドを書けない。

# 破棄した案

- `html` マクロのブロックだけを走査する（フラグメントとヘルパーメソッドが漏れる）
- `label` ブロックのマクロで中の `input` を書き換える
- ビュー全体の `for` と `id` をメソッドをまたいで照合する
