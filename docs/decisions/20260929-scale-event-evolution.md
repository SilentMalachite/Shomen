# 状況

イベントは追記のみで、保存済みの行は起動のたびに読み直す。仕様は、イベント型の形が変わったときや、Crystal の型名を変えたときの扱いを書いていない。

# 決定

保存済みのイベントは書き換えない。イベントの形を変えるときは、新しいイベント型を足すか、既定値のあるフィールドを足す。保存済みの型からフィールドを消したり、名前を変えたりしない。`type` 列には、イベント型が宣言する名前を入れる。Crystal の型名を変えても、この名前は変わらない。

# 理由

保存済みの行は、何年たっても読める必要がある。フィールドが消えたり、型の名前が変わったりすると、過去のイベントを読めなくなり、リードモデルを作り直せなくなる。宣言した名前を `type` に入れれば、コードの整理（名前空間の変更など）と保存形式を切り離せる。

# 破棄した案

- `type` に Crystal の型名をそのまま入れる
- 形が変わったら、保存済みの行を一括で書き換える
- 読み込み時に古い形を新しい形へ変換する層（アップキャスタ）を最初から入れる
